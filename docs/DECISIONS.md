# FORGE — Decisions

| # | Decision | Alternatives considered | Why |
|---|---|---|---|
| 1 | **Tauri 2 + React/TS + Rust core**; Node engine only for provider SDKs | Electron (heavier, no Rust boundary); all-Rust (no official Claude SDK in Rust; would mean re-implementing the control protocol) | Privileged work stays in Rust; Windows-native webview (WebView2 present); small footprint. |
| 2 | **Claude via the official Agent SDK** pointed at the user's installed `claude` | Parse CLI text output (rejected: brief forbids); raw `stream-json` control protocol (SDK implements it supported-ly) | Gets structured events, `interrupt`, resume, hooks, permission callbacks without guessing a wire format. SDK licence is Anthropic's own ("see LICENSE.md"), not OSS — acceptable for local use; review before any redistribution. |
| 3 | **One engine process per session**, JSONL over stdio | One shared multiplexed engine | Cancellation = kill a tree; crash isolation; Job Object per session. |
| 4 | **PreToolUse hook is the enforcement point**, `canUseTool` fallback | `canUseTool` alone | SDK docs: `canUseTool` fires only when a call falls through to a prompt, so user allow-rules would skip FORGE entirely. |
| 5 | **`settingSources:['project']`** (exclude user settings) | CLI default (all sources) | Reproducible missions; user's global allow-rules / `bypassPermissions` can't widen approvals. Trade-off: user-level CLAUDE.md is not loaded (to be revisited with the Context Inspector). |
| 6 | **Git via the Git CLI**, not libgit2 | `git2` crate | Identical behaviour to the developer's git on NTFS (worktrees, long paths, hooks); no native build burden. |
| 7 | **Worktrees under `~/.forge/worktrees`**, branch `forge/<slug>-<id>` from current HEAD | Inside the repo; sibling dir | Keeps repos clean; short paths; no `.gitignore` edits. Known gap: fresh worktrees lack `node_modules`/build caches (per-project setup commands later). |
| 8 | **"Stop" → `interrupted` (resumable); "Discard" → `cancelled`** | Single cancel | Stopping an agent should not destroy its work. |
| 9 | **Core-originated events use negative `seq`** | Separate table | One ordered flight recorder per mission; unique key keeps idempotency. |
| 10 | **SQLite + FTS5 first, embeddings later only if measured** | Vector DB now | Brief requirement; FTS5 confirmed available in bundled SQLite (test). |
| 11 | **Scripted test agent** is gated to debug builds / env flag and labelled "not a real agent" | Mock inside Rust tests only | Lets approvals, crashes, cancel, recovery be tested end-to-end through the real process boundary without spending quota. Live provider behaviour is proven separately by an opt-in live test. |
| 12 | **Docs live in `docs/`**, not the repo root | Root-level docs | Brief: avoid cluttering the root. |
| 13 | **Medium-effort subagent for isolated UI work; high effort for architecture, security, integrations** | Do everything inline | User instruction; UI is isolated behind a frozen contract (`types.ts`/`api.ts`). |
| 14 | **Repo-defined hooks/MCP servers are neutralised** (`allowManagedHooksOnly`, `strictMcpConfig`) while `settingSources:['project']` still loads CLAUDE.md | Exclude project settings entirely; trust the repo | Verified by experiment: a hostile repo's hooks and MCP server run unprompted in SDK sessions; the lockdown stops them and keeps our own hook. |
| 15 | **Local models via the Claude Code harness pointed at loopback Ollama** (`claude-local` provider) | Build a second harness; wait for the Codex adapter | Real agent protocol at zero provider cost (user instruction); loopback-only endpoint enforced in Rust and engine; no cost figure is reported for local models. |
| 16 | **Trust is authoritative in SQLite, bound to the content hash; frontmatter is never trusted** | Store `state:` in page files | A vault edit setting `state: verified` must not grant trust (independent design review). Files stay portable; FORGE shows state, not the file. |
| 17 | **Memory is injected into the first user turn, verified-only, never the system prompt** | System-prompt injection; MCP memory tool | The system prompt is the most privileged channel; a textual delimiter cannot stop semantic injection, so only human-reviewed text is eligible and policy remains the control. An in-process MCP memory tool is a possible later channel. |
| 18 | **Edits to existing pages are revisions applied under a lock with a base-hash check** | Overwrite in place | Obsidian and FORGE can both write; FORGE must never silently clobber a user's note. |
| 19 | **FTS5 `unicode61` + identifier expansion + prefix terms, no Porter** | Porter stemming; embeddings | Precision on code identifiers; embeddings only if measured retrieval fails on real queries. |
| 20 | **Evidence is bound to a change-set fingerprint** (temporary-index tree hash) | Commit hash only | Agents leave uncommitted changes; the fingerprint also covers untracked files and never mutates the real index. |
| 21 | **Real-window verification over CDP is part of "done" for UI work** | Trust unit tests + typecheck | The first real run found three bugs no test could (verbatim-path engine crash, `window.confirm` blocked by Tauri, stale tab data). |
| 22 | **Harness edits are preview → compare-and-swap → journal → backup → atomic write, and every one is reversible** | Edit in place with an "are you sure" | Instruction and settings files steer the agent, so a silent overwrite of a teammate's or a merge's change is worse than a refused save. The user approves a diff of exactly the bytes written (`expected_after_sha256`), the write only happens if the file still has the hash they opened, and the previous bytes are backed up first. |
| 23 | **Only an allowlist of project files is editable; user-level (`~/.claude`) and `.mcp.json` never** | Edit anything under `.claude/` | Narrow blast radius: user-level files affect every project, `.mcp.json` launches programs. FORGE neither loads nor edits them; they are shown read-only. |
| 24 | **Rollback refuses on conflict rather than merging** | Three-way merge; force flag | If the file changed after the edit, restoring the backup would discard that change. FORGE shows why and leaves the file alone; the user edits by hand. |
| 25 | **Unchanged hooks are grandfathered when validating a settings edit; new or modified hooks must pass in full** | Validate the whole file strictly; validate nothing | Strict whole-file validation would block unrelated edits to a file that already has a legacy hook without a timeout; no validation would let a changed hook through. Grandfathered problems are shown as warnings. |
| 26 | **FORGE missions do not run project hooks; the Harness UI says so per hook** | Pretend hooks "work" in missions | The lockdown (decision 14) is deliberate. Hooks written here apply to the user's own Claude Code sessions — verified live (see PROGRESS.md) — and the UI never implies otherwise. |
| 27 | **Hook dry-run executes the real command on explicit user confirmation, with secret-looking environment scrubbed** | Simulate; refuse to run | A simulation cannot show what a hook does. It is the same trust decision as running a check, so it is gated the same way (full command shown, user confirms), time-boxed and tree-killed. It is not a sandbox. |
| 28 | **Core pushes `proofPack`, `knowledge` and `harness` events; views refetch on them** | Poll; refetch only on tab activation | The Proof Pack tab stays mounted and relied on mission-state changes to reload; in the real window a pack sealed by a merge was not shown until later. An explicit event makes the refresh deterministic, and the E2E now asserts the pack appears with no manual refresh. Events are persisted-then-pushed like the rest. |
