## Review 1 — Phase 1 core: security and reliability  (2026-10-23)

Scope: `supervisor.rs`, `policy.rs`, `paths.rs`, `store.rs`, `proc.rs`, `git.rs`, `mission.rs`, and the engine
(`main.ts`, `adapters/claude.ts`, `claudeNormalize.ts`, `fake.ts`). Six questions: approval boundary, concurrency,
Windows containment, path security, data loss, anything else.

## Review 2 — Memory design (before any code)  (2026-10-23)

Scope: the FORGE Memory design as a written brief (files-as-truth + SQLite index, states, retrieval, Obsidian boundary,
injection). Seven questions. Astra's "top 3 design changes before coding": revision-bound verification; untrusted context
out of the system prompt; journaled writes with explicit external-writer conflict handling.

| # | Astra's finding | My assessment | Resolution |
|---|---|---|---|
| 1 | Verification can be forged or inherited: a vault edit sets `state: verified`, or replaces a verified page's body and keeps its status. Bind verification to project/page/**revision hash**/reviewer; imported frontmatter must not grant trust; supersession never transfers verification and rejects cycles transactionally. | Right, and it reshaped the data model. | **Adopted in full.** `status` + `verified_sha256` live in SQLite; frontmatter state/author are ignored; `effective_state` derives from hash equality; `k_verify` compares the reviewer's hash inside the transaction; `k_supersede` walks the chain (tests: forged frontmatter, edit after verify, stale review screen, cycles, atomic rejection). |
| 2 | Retrieved text becomes privileged instruction; keep it out of the system prompt; label origin/status/freshness; collision-safe delimiters; exclude proposed agent text; bound/strip. No delimiter stops semantic injection. | Agree, including the limits. | **Adopted.** Injected into the first *user* turn only; verified-only (user pins are labelled NOT VERIFIED); angle brackets and control chars stripped, embeds neutralised, secrets redacted again on the way out; exact bytes persisted. Test asserts the system prompt never contains it. Residual risk documented. |
| 3 | Canonicalisation leaves races: junction swapped after validation, hardlinks. Reject reparse points and hardlinks in managed trees; broker I/O. | Partly: V1 detects and rejects; handle-based I/O is future work. | **Adopted as detect-and-reject** (`vault::safe_file`, real junction + hardlink tests). TOCTOU remains and is documented. |
| 4 | Atomic replace does not prevent lost updates; use a writer lock, an operation journal, write proposed revisions for externally edited pages; generate `index.md`/`log.md` from durable records. | Right. | **Adopted.** File lock per root; `knowledge_op` journal + hash-based recovery; edits to existing pages are revisions applied only on request with a base-hash check (conflict recorded, nothing overwritten); catalogue files are generated. |
| 5 | Redaction misses other ingestion routes; allowlist/sensitive-file exclusions; retention across snapshots, packages, backups. | Right. | **Adopted:** sensitive-name exclusion at scan and as sources, redaction on create/revision/injection, `forget` scrubs historical snapshots. Backups/export semantics not built yet (SQLite is kept outside sync folders by default). |
| 6 | sha256-at-capture proves identity, not truth; store source type, locator, raw + normalised hashes, git blob/commit pins, extractor version, missing-source states. | Right. | **Adopted:** `knowledge_source` carries all of these; freshness states current/changed/missing/unknown; mission records state "what happened, not whether it was correct". |
| 7 | Incremental indexing can silently miss same-size edits; mtime/watchers are hints; hash selected pages before packaging; persist exact injected bytes; pin per turn. | Right — and I wrote the test that reproduces it. | **Adopted:** retrieval re-hashes every page it is about to inject (mutation-checked: disabling it makes the same-size-edit test fail); packages are pinned to the first turn. A file watcher is not built (scan on open/retrieval instead). |
| 8 | Free text changes MATCH semantics; Porter hurts identifiers; recency rewards poisoned edits; ambiguous links. | Right. | **Adopted:** quoted terms only, `unicode61` + identifier expansion + prefix terms, recency is a small bonus applied only after eligibility, ambiguous wikilinks are recorded not guessed. |

Not adopted: separate immutable review-record store with transactional-only audit (the `knowledge_review` table in the same
database serves; the generic best-effort `audit()` is not used for verification), in-process MCP memory channel (V2).

## Review 3 — implemented Phase 2 (verification, merge) and Phase 3 (memory)  (2026-10-23)

Scope: `contract.rs`, `verify.rs`, `proof.rs`, `merge.rs`, `store_review.rs`, `supervisor/review.rs`, all of `knowledge/`,
`supervisor/memory.rs`. Thirteen findings; "top 3": immutable reviewed-to-merged snapshots; disable uncontrolled Git
execution; bind knowledge text and trust atomically.

| # | Finding (Astra) | My assessment | Resolution / evidence |
|---|---|---|---|
| 1 | The approved tree can differ from the committed tree: an ignored file force-staged in the *real* index is absent from the preview index but is committed by `git add -A`; branch/target are resolved by mutable names. | Confirmed in design. | **Fixed.** Merge commits the *reviewed tree* via `commit-tree` (never the real index), advances the mission branch with a compare-and-swap `update-ref`, resolves branch and target to object ids once, predicts the merge with `git merge-tree`, and compares the result tree with the prediction. Tests: `a_force_staged_ignored_file_does_not_ride_along_into_the_merge`, `the_commit_is_the_reviewed_tree…`, `a_result_that_differs_from_the_prediction_is_undone`. |
| 2 | Previewing/reviewing can execute repository-controlled programs (hooks, clean/smudge filters, merge drivers); `--no-verify` does not suppress all hooks. | Confirmed. | **Fixed.** Every supervised git call runs with `core.hooksPath` pointing at an empty directory; repositories configuring non-system `filter.*` or `merge.*.driver` programs are refused before anything runs (Git LFS recognised). *Found while testing:* Git for Windows ships `diff.astextplain.textconv` in its **system** config, so the first version of this check blocked every Windows user; scoped it to what can actually execute (filters, merge drivers) and to non-system scopes. Tests: `a_hostile_git_hook_never_runs_during_review_or_merge`, `repository_hooks_never_run_during_supervised_git_calls`, `repositories_configuring_external_git_programs_are_refused`. |
| 3 | Unreviewed knowledge can be injected as verified: retrieval hashes the file then separately reads the cached body. | Confirmed. | **Fixed.** One read yields the injected text and the hash; trust is judged on that hash against the verified revision; the cached body is never what the agent reads. Page detail returns `textSha256` for verification. Test: `injected_text_is_the_verified_file_content_never_a_different_database_body`. |
| 4 | Approval is not bound to what the reviewer saw (`review`/`set_manual_verdict` recompute state). | Confirmed. | **Fixed.** Approving requires `Seen{fingerprint, contractSha256}`; verdicts require the expected fingerprint; mismatches are refused. Tests: `an_approval_names_what_the_reviewer_saw_and_nothing_else_is_accepted`, `a_manual_verdict_is_refused_if_the_changes_moved…`. |
| 5 | Merge can destroy main-checkout work: ignored files are overwritten by default; any failure triggers `reset --hard`. Suggested fix: `--no-overwrite-ignore`. | Confirmed the problem. **The suggested fix does not work**: I reproduced it with plain git 2.55 — the flag is accepted and the ignored file is still silently replaced (exit 0). | **Fixed differently.** FORGE diffs the current tree against the predicted result and refuses if any touched path already exists untracked in the checkout; failures use `merge --abort` / `reset --merge` (keep local work) and only when HEAD is where FORGE left it; `reset --hard` removed. Tests: `ignored_files_in_the_main_checkout_are_never_overwritten`, `merging_never_overwrites_an_ignored_local_file…`, `a_failed_merge_restores_the_checkout_and_never_discards_local_work`. |
| 6 | "Merged" cleanup can delete subsequent commits without confirmation (merged missions were exempt). | **Confirmed — a bug I wrote.** | **Fixed.** No exemption; safety is judged against what actually reached the main checkout's HEAD. Test: `cleanup_after_a_merge_protects_commits_added_to_the_branch_afterwards`. |
| 7 | `start_check` tests ownership then registers non-atomically; finalisation releases the slot before killing descendants. | Confirmed. | **Fixed.** The check claims the mission in the same critical section that proves nothing else owns it; finalisation terminates the Job before releasing the mission. Test: `a_check_cannot_start_while_another_operation_owns_the_mission`, plus the existing descendant-kill test. |
| 8 | Evidence survives changes to its meaning: edit a check's command or a criterion's text and old results still verify it; mutated runs not excluded. | Confirmed. | **Fixed.** Runs carry the check-definition revision; verdicts carry the criterion revision; a changed definition makes old evidence inconclusive; a run that mutated the worktree is categorically not evidence; approvals are bound to the contract revision. Tests: `editing_a_checks_command_after_it_passed_voids_the_evidence`, `a_pass_does_not_carry_over…`, `a_manual_verdict_does_not_survive_an_edit…`. |
| 9 | Secrets persist via paths that bypass redaction (check logs, proof diffs, imported note bodies, forget leaves excerpts and orphan snapshots). | Partly. | **Fixed:** check logs redacted line by line; stored/searchable page bodies redacted (the user's file and its hash are never rewritten); `forget` removes the quoted *items* (not just ids) and deletes orphaned source snapshots. **Not changed, by design:** the Proof Pack diff file stays byte-exact (its hash is meant to be verifiable) and therefore holds the user's code verbatim — documented in SECURITY.md. |
| 10 | Recovery bypasses vault write permission and filesystem checks (deletes `.forge-tmp-*` in every root, even read-only; `safe_file` checks only canonicalised components). | Confirmed — including that an internal junction aimed elsewhere inside the tree was invisible after canonicalisation. | **Fixed.** Recovery touches only writable roots, under the lock, in FORGE's own folder, never through a link; `safe_file` now walks the *spelled* path for links before canonicalising. Tests: `recovery_leaves_read_only_vaults_and_links_alone`, `a_junction_that_points_elsewhere_inside_the_same_tree_is_still_refused`. |
| 11 | Scope checks miss moved excluded files (rename parsing drops the old path), case-sensitive globs on Windows, and `scope_rule` returns before other requirements. | Confirmed. | **Fixed.** `--no-renames` lists both endpoints; globs are case-insensitive on Windows; scope is one requirement among others and can no longer hide linked checks or a required human verdict. Tests in `contract::tests`. |
| 12 | One missing page hides the whole root (`reindex_page` marks every page missing); unchanged-signature skip never restores missing rows. | **Confirmed — a bug I wrote.** | **Fixed.** Only the absent page is marked; a returned file is always re-read. Tests: `one_missing_page_does_not_hide_every_other_page`, `a_page_whose_file_comes_back_is_restored…`. |
| 13 | Exit zero is promoted to criterion verification without assertion evidence (an agent can make `npm test` a no-op). | Accepted as a limitation of the model. | **Mitigated, not solved:** the report flags changed files that define or configure a check (script, manifests, test configs, CI) and lists them under "not established"; `mutated` runs are excluded. A passing check remains *evidence*, never proof (stated in every Proof Pack). Test: `changes_to_files_that_define_a_check_are_called_out` (and a heuristic false positive on the subject of a check was caught and removed while writing it). |

Validation: Rust 239 tests (3 live ignored), engine 36, all pass.
