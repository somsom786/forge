## Review 2 — Memory design (before any code)  (2026-10-23)

Scope: the FORGE Memory design as a written brief (files-as-truth + SQLite index, states, retrieval, Obsidian boundary,
injection). Seven questions. Astra's "top 3 design changes before coding": revision-bound verification; untrusted context
out of the system prompt; journaled writes with explicit external-writer conflict handling.

| # | Astra's finding | My assessment | Resolution |
|---|---|---|---|
| 1 | Verification can be forged or inherited: a vault edit sets `state: verified`, or replaces a verified page's body and keeps its status. Bind verification to project/page/**revision hash**/reviewer; imported frontmatter must not grant trust; supersession never transfers verification and rejects cycles transactionally. | Right, and it reshaped the data model. | **Adopted in full.** `status` + `verified_sha256` live in SQLite; frontmatter state/author are ignored; `effective_state` derives from hash equality; `k_verify` compares the reviewer's hash inside the transaction; `k_supersede` walks the chain (tests: forged frontmatter, edit after verify, stale review screen, cycles, atomic rejection). |
| 2 | Retrieved text becomes privileged instruction; keep it out of the system prompt; label origin/status/freshness; collision-safe delimiters; exclude proposed agent text; bound/strip. No delimiter stops semantic injection. | Agree, including the limits. | **Adopted.** Injected into the first *user* turn only; verified-only (user pins are labelled NOT VERIFIED); angle brackets and control chars stripped, embeds neutralised, secrets redacted again on the way out; exact bytes persisted. Test asserts the system prompt never contains it. Residual risk documented. |
| 3 | Canonicalisation leaves races: junction swapped after validation, hardlinks. Reject reparse points and hardlinks in managed trees; broker I/O. | Partly: V1 detects and rejects; handle-based I/O is future work. | **Adopted as detect-and-reject** (`vault::safe_file`, real junction + hardlink tests). TOCTOU remains and is documented. |
| 4 | Atomic replace does not prevent lost updates; use a writer lock, an operation journal, write proposed revisions for externally edited pages; generate `index.md`/`log.md` from durable records. | Right. | **Adopted.** File lock per root; `knowledge_op` journal + hash-based recovery; edits to existing pages are revisions applied only on request with a base-hash check (conflict recorded, nothing overwritten); catalogue files are generated. |
| 5 | Redaction misses other ingestion routes; allowlist/sensitive-file exclusions; retention across snapshots, packages, backups. | Right. | **Adopted:** sensitive-name exclusion at scan and as sources, redaction on create/revision/injection, `forget` scrubs historical snapshots. Backups/export semantics not built yet (SQLite is kept outside sync folders by default). |
| 6 | sha256-at-capture proves identity, not truth; store source type, locator, raw + normalised hashes, git blob/commit pins, extractor version, missing-source states. | Right. | **Adopted:** `knowledge_source` carries all of these; freshness states current/changed/missing/unknown; mission records state "what happened, not whether it was correct". |
| 7 | Incremental indexing can silently miss same-size edits; mtime/watchers are hints; hash selected pages before packaging; persist exact injected bytes; pin per turn. | Right — and I wrote the test that reproduces it. | **Adopted:** retrieval re-hashes every page it is about to inject (mutation-checked: disabling it makes the same-size-edit test fail); packages are pinned to the first turn. A file watcher is not built (scan on open/retrieval instead). |
| 8 | Free text changes MATCH semantics; Porter hurts identifiers; recency rewards poisoned edits; ambiguous links. | Right. | **Adopted:** quoted terms only, `unicode61` + identifier expansion + prefix terms, recency is a small bonus applied only after eligibility, ambiguous wikilinks are recorded not guessed. |

Not adopted: separate immutable review-record store with transactional-only audit (the `knowledge_review` table in the same
database serves; the generic best-effort `audit()` is not used for verification), in-process MCP memory channel (V2).

## Review 3 — implemented Phase 2 (verification, merge) and Phase 3 (memory)  (2026-10-23)

Scope: `contract.rs`, `verify.rs`, `proof.rs`, `merge.rs`, `store_review.rs`, `supervisor/review.rs`, all of `knowledge/`,
`supervisor/memory.rs`. Thirteen findings; "top 3": immutable reviewed-to-merged snapshots; disable uncontrolled Git
execution; bind knowledge text and trust atomically.

| # | Finding (Astra) | My assessment | Resolution / evidence |
|---|---|---|---|
| 1 | The approved tree can differ from the committed tree: an ignored file force-staged in the *real* index is absent from the preview index but is committed by `git add -A`; branch/target are resolved by mutable names. | Confirmed in design. | **Fixed.** Merge commits the *reviewed tree* via `commit-tree` (never the real index), advances the mission branch with a compare-and-swap `update-ref`, resolves branch and target to object ids once, predicts the merge with `git merge-tree`, and compares the result tree with the prediction. Tests: `a_force_staged_ignored_file_does_not_ride_along_into_the_merge`, `the_commit_is_the_reviewed_tree…`, `a_result_that_differs_from_the_prediction_is_undone`. |
| 2 | Previewing/reviewing can execute repository-controlled programs (hooks, clean/smudge filters, merge drivers); `--no-verify` does not suppress all hooks. | Confirmed. | **Fixed.** Every supervised git call runs with `core.hooksPath` pointing at an empty directory; repositories configuring non-system `filter.*` or `merge.*.driver` programs are refused before anything runs (Git LFS recognised). *Found while testing:* Git for Windows ships `diff.astextplain.textconv` in its **system** config, so the first version of this check blocked every Windows user; scoped it to what can actually execute (filters, merge drivers) and to non-system scopes. | 4 | Approval is not bound to what the reviewer saw (`review`/`set_manual_verdict` recompute state). | Confirmed. | **Fixed.** Approving requires `Seen{fingerprint, contractSha256}`; verdicts require the expected fingerprint; mismatches are refused. | 9 | Secrets persist via paths that bypass redaction (check logs, proof diffs, imported note bodies, forget leaves excerpts and orphan snapshots). | Partly. | **Fixed:** check logs redacted line by line; stored/searchable page bodies redacted (the user's file and its hash are never rewritten); `forget` removes the quoted *items* (not just ids) and deletes orphaned source snapshots. **Not changed, by design:** the Proof Pack diff file stays byte-exact (its hash is meant to be verifiable) and therefore holds the user's code verbatim — documented in SECURITY.md. |

## Review 5 — Codex adapter  (2026-10-23, GPT-6.1 Sol, high effort, read-only)

Before the review I found by experiment that a repository's `.codex/config.toml` MCP server runs although Codex calls project config untrusted,
that `config/read` inside a git worktree omits servers `thread/start` still starts, and that only per-name `enabled=false` disables a server.
The adapter therefore refuses repositories with project Codex config. The reviewer found 5 HIGH, 3 MEDIUM, 1 LOW; it also confirmed several safeguards
(per-path file approvals, no `acceptForSession`, unsupported requests answered with errors, Job Object containment, redaction).

| # | Finding | Resolution |
|---|---|---|

| 2 HIGH | User/project exec allow-rules run commands with no approval request | **Reproduced** here (`rg --version` ran unprompted from the user's `default.rules`). **Mitigated by refusing**: a Codex mission will not start while the Codex home has allow rules (explicit opt-in `FORGE_CODEX_ALLOW_USER_RULES=1`). `askForApproval.granular` needs an experimental capability and does not remove allow-rules. A cleaner fix (an isolated Codex home) is blocked by the login living in that home; not done. |
| 3 HIGH | API billing still possible (stored API-key login, custom provider); env scrub case-sensitive | **Fixed**: `account/read` must report `chatgpt` before any thread starts; provider pinned (`openai`/`ollama`); env names scrubbed case-insensitively |
| 4 HIGH | `notify` runs commands outside hooks; `CODEX_HOME` could sit inside the repo | **Fixed**: `-c notify=[]`; refuses a Codex home inside the repository |
| 5 HIGH | Native web search has no FORGE gate | **Fixed**: `-c web_search="disabled"`. Image generation / sub-agent / unexpected MCP items have no gate but their prerequisites (plugins, apps, multi-agent, MCP) are disabled; not independently proven |

| 9 LOW | Detection and launch use different Codex resolvers | **Fixed**: one resolver (`locate_codex`), including the override |
